# Linear

Sources read: 2026-10-10. Release documentation is undated; publication dates identify the engineering accounts.

Linear's remote-work account, dated 2025-10-29, describes small project teams with clear ownership. Its design-refresh account, dated 2026-03-12, describes engineers and designers using coding agents. It describes a PR and "preview build" review loop, then an in-app color tool built with Claude Code to shorten visual iteration. [Designing remote work at Linear](https://linear.app/now/designing-remote-work-at-linear), [Design refresh account](https://linear.app/now/behind-the-latest-design-refresh).

Its main application deploys continuously from main, while production mobile releases remain scheduled. New features reach internal users behind switches first, with selected customers joining when useful. Deployment and broad exposure are separate decisions. [Releases](https://linear.app/docs/releases), [Internal-first practice](https://linear.app/now/designing-remote-work-at-linear).

The review article dated 2026-05-28 emphasizes customer purpose and review speed. Its guided review of a large change does not establish a mandatory small-PR limit. The incident account dated 2024-01-30 describes local tests, CI warnings and several engineer reviewers, without establishing the complete current approval policy. [Code review should be fast](https://linear.app/now/code-review-should-be-fast), [Incident account](https://linear.app/now/linear-incident-on-jan-24th-2024).

Linear's bug policy, dated 2025-09-24, sets deadlines for fixing high-priority and other bugs, while allowing explicit decisions not to fix. The published practice connects tracking with responsibility rather than letting all bug reports remain indefinitely open. [Zero bugs policy](https://linear.app/now/zero-bugs-policy).
